# GameLens native game control

- In multi-client mode call `gamelens_clients` first and supply the exact `client` name on every session/state/see/act/recording call. Ten slots are preconfigured; launch only the sessions needed. Keep each client's observations and recording separate. Different games can occupy different slots: identify the current game before using its saved controls, and never apply the GodsArena profile to another game.
- Call `gamelens_state`, then `gamelens_see`. Confirm the selected window, capture health, geometry and foreground before input. For an owner-authorized game task, an authenticated agent may call `gamelens_session` action `arm`, then `live`, without requiring another owner click. Startup remains disarmed/dry-run; enabling a session sends no game input.
- Use `gamelens_act` with coordinates from the last image. Prefer one short verified sequence for known navigation/menu steps; observe its outcome before another decision. `strict:true` preserves the short freshness limit. A saved snapshot lasting120s does not make its action indefinitely safe.
- `sent` means injected, not completed gameplay. Require the resulting screen/receipt. A refusal returns a fresh image; decide from it. A sequence may have executed partly: never replay it blindly. Stop when session/window/geometry/focus changes or held inputs remain.
- Shared foreground mouse/keyboard still apply. Owner mouse movement can invalidate a pending action. This plugin grants no background-input driver or separate virtual controls. F12/Pause remains the emergency kill switch.
- The MCP uses the agent credential. Owner policy permits authenticated agents to Arm/Go live for an instructed task, including an instruction received remotely. Use explicit `gamelens_session` actions `status`, `arm`, `live`, `stop`; select the client on every multi-client call. `stop` latches the session off; Arm/Live cannot clear an emergency stop. Do not use operator credentials or start a race, record, focus the game, change provider/model or spend currency solely because this skill loaded. Inspect status after an uncertain response; never blindly retry.
- If the intended local GameLens server is closed and the owner requested running it, use the companion project's `.venv/Scripts/pythonw.exe GameLens.pyw --target <verified window HWND> --port <selected client port>`. Inspect available windows with `.venv/Scripts/python.exe -m gamelens --list`; verify the exact game first. Wait for authenticated healthy state, then use explicit Arm/Live. Do not select another game, launch all slots, or expose the loopback API publicly. See `docs/AGENT_SESSION.md`.
- For GodsArena Marathon, use the companion `gamelens-godsarena` skill or read `gamelens_profile` once. Reuse the learned route, then verify current state. Do not reread the whole game wiki each run or present historical positions/eligibility as live facts.
- Use `gamelens_recording` action `status`, `start` or `stop` for the selected capture window. Start accepts fps15/30/60 (default30); output is video only, no audio. For an owner-authorized Marathon recording, check status and start once before race Start, then stop after finish or interruption. An already-active recording needs no duplicate start. If a request fails, check status before deciding; never blindly retry. Recording does not arm, go live, focus, send game input or open an arbitrary path.
- Save useful checkpoints, actual results and exact continuation in the existing project log. Avoid raw transcripts, credentials and private reasoning.

The plugin requires the local GameLens installation and its Windows-encrypted agent handoff. It starts only the MCP client, never the game or a race.
